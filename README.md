# WebEducation

WebEducation — образовательная платформа для самостоятельной подготовки
школьников 1–9 классов по спортивному программированию. В проекте есть кабинеты
ученика, куратора и администратора, курсы с модулями и разными типами заданий,
автоматическая и ручная проверка работ, вопросы внутри шага и объяснимый
прогресс.

## Что уже реализовано

- вход по сессионной авторизации и ролевой доступ для ученика, куратора и
  администратора;
- каталог назначенных курсов, паспорт курса, модули и последовательное
  прохождение шагов;
- теория в Markdown, контрольные вопросы, точные ответы, Scratch, Minecraft
  Education и алгоритмические задачи на Python;
- редактор и публикация курсов с неизменяемыми опубликованными версиями;
- автоматическая проверка ответов и Python-кода на сервере, ручная проверка
  файлов, ссылок и пояснений куратором;
- защищённые вложения и превью изображений, вопросы по конкретному шагу,
  комментарии к проверке и повторная сдача;
- прогресс, баллы, следующее действие ученика и сигналы отставания для
  куратора;
- официальный учебный пакет организатора: 3 курса, 9 модулей и 30 шагов;
- светлый интерфейс на основе брендбука образовательной платформы.

## Быстрый запуск через Docker

Нужны Docker Engine или Docker Desktop с Compose v2.

```bash
git clone https://github.com/D0UP1G/WebEducation.git
cd WebEducation
./scripts/start-demo.sh
```

В Windows Command Prompt используйте `scripts\start-demo.cmd`.

После сборки откройте <http://localhost:8080/>. API healthcheck доступен по
<http://localhost:8080/api/v1/health>. Скрипт создаёт `.env` из `.env.example`,
запускает PostgreSQL, Django, reverse proxy и изолированный Python-runner,
применяет миграции и загружает официальный учебный пакет.

Чтобы открыть демо другим устройствам в той же локальной сети:

```bash
./scripts/start-demo.sh --lan 192.168.1.25
```

Подставьте частный IPv4-адрес компьютера с Docker. Подробные настройки
развёртывания, LAN, HTTPS, лимитов и runner находятся в
[документации по запуску](docs/deployment.md).

Остановить локальный стенд:

```bash
docker compose down
```

Именованные тома Docker при этом сохраняются. Резервное копирование и
восстановление описаны в [документации по базе данных](docs/database.md).

## Демо-аккаунты

Команда `seed_demo` создаёт синтетические аккаунты. Пароль для всех аккаунтов —
`demo`.

| Роль | Логин |
| --- | --- |
| Администратор | `admin_demo` |
| Куратор | `curator_demo` |
| Ученик | `student_demo` |

Демо-стенд предназначен для проверки продукта и не должен использоваться для
реальных персональных данных.

## Локальная разработка без Docker

Для backend используйте Python 3.13, для frontend — Node.js 22 и npm (такие же
версии используются в контейнерах).

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cd backend
../.venv/bin/python manage.py migrate
../.venv/bin/python manage.py seed_demo
DJANGO_CSRF_TRUSTED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173 \
  ../.venv/bin/python manage.py runserver
```

В отдельном терминале запустите frontend:

```bash
cd frontend
npm ci
npm run dev
```

Откройте <http://localhost:5173/>. Vite проксирует API на Django-порт 8000.
Для обычной работы достаточно Docker-варианта из предыдущего раздела.

## Проверка проекта

Backend:

```bash
cd backend
../.venv/bin/python manage.py check
../.venv/bin/python manage.py test
```

Frontend:

```bash
cd frontend
npm run typecheck
npm test
npm run build
```

Проверка и повторный импорт учебного пакета описаны в
[документации по базе данных](docs/database.md) и в
[материалах организатора](docs/organizer/README.md).
