# MVP-аудит · 24 сентября 2026

Основа: [кейс проекта](../keys-obrazovatelnaya-platforma.pdf), `docs/case-alignment.md`, код и тесты `develop` после PR #23. Статус ниже не равен приёмке на публичном стенде.

## Вердикт

Функциональный каркас MVP есть: роли ученика, куратора и администратора; создание и назначение курсов; семь типов шагов; автоматическая и ручная проверка; вопросы; прогресс и сигналы застоя. Локальные тесты и сборка проходят. **Полное соответствие кейсу и готовность публичного стенда пока не подтверждены.**

## Исправлено в этой ветке

| Приоритет | Проблема | Исправление |
|---|---|---|
| P0 | Nginx перехватывал `/admin/` и отправлял React-маршруты администратора в Django, где они не существуют. | Оба шаблона Nginx отдают `/admin/*` как SPA; `/api/*` по-прежнему проксируется в backend. |
| P1 | Куратор видел сдачу и вопрос без формулировки задания и названия курса. | API отдаёт публичное содержимое шага; UI показывает его. Правильные ответы и тесты скрываются тем же санитайзером, что используется для ученика. |
| P1 | HTTPS-профиль не включал `Secure` для cookie и мог стартовать с примерным ключом и debug. | Профиль принудительно задаёт `DEBUG=0` и защищённые cookie; backend отказывается запускаться с примерным или отсутствующим ключом. |

## Открытые препятствия

1. **Несоответствие кейсу — правило публикации.** Кейс требует теорию и контрольный вопрос; по прямому решению владельца обязателен только шаг «Теория». Код следует этому решению, но формально не соответствует кейсу. Нужно отдельное решение владельца перед защитой.
2. **Python-оценка не является защищённой.** Python выполняется в браузере ученика, а сервер сравнивает заявленный клиентом вывод с ожидаемым. Подпись challenge связывает ученика, шаг и исходный текст кода, но не доказывает, что именно этот код был исполнен. Технически ученик может подменить результаты, поэтому такую проверку нельзя использовать для доверенной оценки без серверного изолированного запуска или ручного подтверждения.
3. **Нет подтверждённого публичного стенда.** На машине аудита отсутствует Docker/Podman/Nginx CLI и нет целевого домена/сертификата. Compose, TLS, backup/restore и полный браузерный маршрут требуют проверки на реальном хосте. Адрес стенда пока не указан в README.
4. **Демо-аккаунты имеют известный пароль `demo`.** Они пригодны только для синтетических данных и демонстрации. Не вводить реальные данные учащихся и не выдавать стенд за production-систему.
5. **Pyodide загружается извне.** На целевом стенде надо проверить его доступность из браузеров участников; при блокировке CDN разместить runtime локально.
6. **CI и защита веток отсутствуют.** Ветки `main` и `develop` не защищены, прямой push возможен. Готовый workflow не удалось отправить: текущий OAuth-доступ GitHub отклонил изменение `.github/workflows/ci.yml` без scope `workflow`. Нужен доступ с этим правом, затем включить проверки и защиту веток.
7. **Две удалённые дизайн-ветки не влиты.** `feature/brandbook` и `feature/theme-refinement` содержат черновой брендбук и статический прототип, не рабочие экраны приложения. Для MVP их не объединяли без отдельной проверки дизайна; остальные проверенные PR #1–#23 объединены.

`manage.py check --deploy` при включённых защищённых cookie оставляет два предупреждения: перенаправление HTTP→HTTPS реализовано в Nginx, а HSTS намеренно не включён до проверки постоянного домена и сертификата.

## Критерий окончательной приёмки

На публичном HTTPS-адресе с синтетическими данными пройти роль администратора (создать курс, опубликовать, назначить), ученика (теория, оба варианта quiz, точный ответ, Python, Scratch и Minecraft, вопросы, история и прогресс) и куратора (ответ, возврат с комментарием, пересдача, принятие, сигнал застоя). Отдельно проверить, что `/admin/courses` и `/admin/assignments` открываются при прямом заходе и обновлении страницы, а новая версия курса не меняет старое назначение. Проверить восстановление БД и media из резервной копии. Пока этот маршрут не пройден, статус — «локально готово к интеграции», не «принято MVP».
