# Документация команды

Начинать работу следует с этого файла и документов в указанном порядке:

1. [Backend handoff](backend-handoff.md) — исходный каркас, команды и владельцы файлов.
2. [DEV-3 handoff](dev3-handoff.md) — сдачи, проверка, куратор и текущие результаты.
3. [API-контракт](api-contract.md) — согласованные маршруты, payload и статусы.
4. [План команды](team-work-plan.md) — зоны ответственности и GitFlow.
5. [Пользовательские потоки](user-flows.md) — ожидаемое поведение интерфейса.
6. [Сверка с кейсом](case-alignment.md) — критерии приёмки и границы MVP.

Архитектурные решения верхнего уровня находятся в `../ARCHITECTURE.md`, порядок
приоритетов — в `../ROADMAP.md`, запуск — в `../README.md`.

## Точка отсчёта

Backend-каркас DEV-1 и frontend DEV-2 уже влиты в `develop`. Перед новой
задачей обновить `develop` и создать от него короткую feature-ветку.

Фактическое состояние определяется кодом и [backend-handoff.md](backend-handoff.md).
Если проектный документ говорит, что кода ещё нет, это устаревшее описание.

## Обязательное правило координации

- DEV-1 — общая схема, миграции, `config`, `accounts`, `courses`, Compose.
- DEV-2 — `frontend/`.
- DEV-3 — `grading`, `mentoring`, `progress` и браузерная проверка Python;
  текущий статус — в [DEV-3 handoff](dev3-handoff.md).
- Изменение общего API, `learning/models.py`, начальных миграций или корневых URL
  сначала фиксируется в коротком согласовании с DEV-1.
- Feature-ветки направляются только в `develop`; `main` и `develop` напрямую не
  изменяются.
