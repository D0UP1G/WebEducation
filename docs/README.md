# Документация для команды и агентов

Начинать работу следует с этого файла и документов в указанном порядке:

1. [Backend handoff](backend-handoff.md) — фактическое состояние кода, команды,
   владельцы файлов и ближайшие задачи DEV-2/DEV-3.
2. [API-контракт](api-contract.md) — согласованные маршруты, payload и статусы.
3. [План команды](team-work-plan.md) — зоны ответственности и GitFlow.
4. [Пользовательские потоки](user-flows.md) — ожидаемое поведение интерфейса.
5. [Сверка с кейсом](case-alignment.md) — критерии приёмки и границы MVP.

Архитектурные решения верхнего уровня находятся в `../ARCHITECTURE.md`, порядок
приоритетов — в `../ROADMAP.md`, запуск — в `../README.md`.

## Точка отсчёта

Backend-каркас подготовлен DEV-1 в ветке `feature/platform-core`. До начала
работы проверить, что эта ветка уже влита в `develop`. Если PR ещё не влит, не
копировать файлы вручную и не создавать альтернативный каркас: дождаться merge
либо явно базировать временную ветку на `origin/feature/platform-core`.

Фактическое состояние определяется кодом и [backend-handoff.md](backend-handoff.md).
Если проектный документ говорит, что кода ещё нет, это устаревшее описание.

## Обязательное правило координации

- DEV-1 — общая схема, миграции, `config`, `accounts`, `courses`, Compose.
- DEV-2 — `frontend/`.
- DEV-3 — `grading`, `mentoring`, `progress` и worker.
- Изменение общего API, `learning/models.py`, начальных миграций или корневых URL
  сначала фиксируется в коротком согласовании с DEV-1.
- Feature-ветки направляются только в `develop`; `main` и `develop` напрямую не
  изменяются.
