## Что остаётся до приёмки

- **Решение владельца MVP-01.** Кейс требует теорию и контрольный вопрос, текущее правило публикации — только теория. Код не менялся до выбора владельца.
- **Доверенная оценка MVP-02.** Браузерный Python допускает подмену результатов. Для защищённой оценки нужен изолированный серверный исполнитель или обязательная ручная проверка; текущие баллы нельзя использовать для значимых решений.
- **Публичный стенд MVP-03/11.** На этой машине есть Docker CLI, но нет `docker compose` и daemon. HTTPS, Nginx-маршруты, полная работа трёх ролей, backup/restore в томах и CDN Pyodide не прошли приёмку на хосте. Нужны домен, сертификат и отдельный протокол с датой, URL и результатом каждого шага.
- **CI MVP-07.** Право `workflow` теперь есть, CI-файл добавлен. Дождаться зелёного первого запуска, затем включить обязательные проверки и review для `develop` и `main` с правами администратора репозитория.
- **Материалы MVP-10 и дизайн MVP-18.** Пакет организатора и финальный брендбук не подтверждены; не подменять их синтетическим seed без явной пометки.
- **Релиз MVP-12.** `main` не обновлять до закрытия P0 и стендовой приёмки; потом release PR по GitFlow.
- **Прочее P2.** Контракт для восьмого типа (MVP-15), глубокая проверка вложений (MVP-16), чистка исторических документов (MVP-17) остаются отдельными работами.

Не считать локальные модульные тесты доказательством безопасной публичной эксплуатации. Использовать только синтетические данные до стендовой приёмки.
