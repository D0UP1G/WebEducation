Текущие владельцы и критерии находятся в [плане](team-work-plan.md), полная сверка — в [аудите](current-gap-analysis.md). По MVP-01 владелец выбрал правило кейса: теория и контрольный вопрос обязательны при публикации; серверная проверка добавлена в обновлённом коде. MVP-04/05/06/08/13/14 исправлены в коде; GitHub CI по MVP-07 прошёл, но защита main/develop ещё выключена. MVP-10 закрыт локально: пакет 3 курса / 9 модулей / 30 шагов импортируется идемпотентно и публикуется через `seed_demo`; остаются стендовая и E2E-приёмка. Официальный брендбук подключён к рабочему UI. Для защищённого Python-зачёта требуется официальный изолированный серверный запуск кода при локальной самопроверке в браузере. Описания ниже являются историческими и не должны назначаться агентам без этой актуализации.

Это **все выявленные на данном срезе проблемы**, а не гарантия отсутствия других: публичный стенд и полный браузерный сценарий ещё не проверены.

**История после PR #26:** MVP-13 был закрыт; MVP-04/05/06/08/14 и CI-файл вошли в develop через PR #27. Подробности — в [отчёте об устранении](mvp-remediation-2026-09-24.md). Описания ниже сохранены как исходные находки, а не текущая оценка исправленного кода.

Статусы: **подтверждено** — следует из конкретного кода или настроек; **не проверено** — результат зависит от стенда или внешних материалов; **решение владельца** — сознательное расхождение, требующее выбора. Приоритет P0 блокирует строгую приёмку MVP по кейсу или доверие к ключевой функции; P1 существенно мешает эксплуатации; P2 — качество и масштабирование.

## P0 — до строгой приёмки

### MVP-01 · В публикации не обязателен контрольный вопрос — решение владельца

Кейс, раздел 04 «Устройство курса», требует в **любом** курсе теорию и контрольный вопрос. Сейчас [публикация](../backend/apps/courses/services.py) проверяет только наличие `theory`: это соответствует последнему прямому решению владельца, но формально не кейсу. Минимальный курс из одной теории можно опубликовать.

**Закрытие:** владелец письменно выбирает, какой критерий важнее для защиты; при выборе требований кейса сервер и тесты требуют `theory` плюс хотя бы один контрольный вопрос (`quiz.single_choice` или `quiz.multiple_choice`). Пока выбран режим «только теория», в демонстрационном курсе вопрос всё равно должен быть.

### MVP-02 · Python-оценку можно обойти подменой результата — подтверждено

[Браузерный worker](../frontend/src/features/student/pythonWorker.ts) запускает код и отправляет `stdout`, время и память; [сервер](../backend/apps/grading/services.py) сверяет присланные значения с ожидаемыми, но **не запускает исходный код**. Подписанный challenge привязан к ученику, шагу и хэшу кода, но не доказывает выполнение этого кода и честность метрик. Поэтому принятие алгоритмической задачи нельзя считать доверенной автоматической проверкой.

**Закрытие:** изолированный серверный запуск с лимитами CPU/памяти/времени и закрытыми тестами либо явная ручная проверка таких задач; добавить тест на попытку подмены результатов. До этого не использовать баллы Python для значимых решений.

### MVP-03 · Публичный HTTPS-стенд не принят — не проверено

В [README](../README.md) нет проверенного публичного URL. На машине аудита нет Docker, Podman и Nginx CLI; сборка Compose, реальный сертификат, маршруты SPA через Nginx и полный путь трёх ролей не проверялись на целевом хосте. `localhost:5174` — локальный dev-сервер, не доказательство публичного развёртывания.

**Закрытие:** разместить синтетический стенд с HTTPS, указать URL в README, повторить [сквозной сценарий](case-alignment.md#приёмка-ядра), включая прямой заход и обновление `/admin/courses` и `/admin/assignments`, оба механизма проверки и сохранение старой версии курса.

## P1 — эксплуатация и защита данных

### MVP-04 · Нет публичного сценария создания учеников и кураторов — подтверждено

API [`/api/v1/admin/users`](../backend/apps/courses/admin_urls.py) поддерживает только список; React-кабинет умеет выбрать существующих пользователей, но не создать их. Django admin имеет форму пользователя, однако после исправления конфликта маршрутов `/admin/*` в публичном Nginx принадлежит React и Django admin там недоступен. Без CLI/прямого backend-доступа администратор не может завести нового участника.

**Закрытие:** безопасная форма/API для создания и деактивации пользователей с ролями, проверкой пароля и прав администратора либо документированный защищённый отдельный канал администрирования. Пройти создание нового ученика → назначение курса без `seed_demo`.

### MVP-05 · Демо-секреты остаются значениями по умолчанию — подтверждено

[`.env.example`](../.env.example) содержит примерный секрет, `DEBUG=1` и известный пароль БД; [`seed_demo`](../backend/apps/accounts/management/commands/seed_demo.py) создаёт пользователей с паролем `demo`. [Compose](../docker-compose.yml) также имеет пароль БД по умолчанию. HTTPS-профиль уже выключает debug, включает secure-cookie и отвергает **известные примерные** ключи, но короткий произвольный ключ и стандартный пароль БД автоматически не запрещаются. Публичный запуск с этими значениями опасен.

**Закрытие:** отдельный fail-closed production-профиль с обязательными секретами/доменом, уникальные пароли, только синтетические данные на демо-стенде; прогнать `manage.py check --deploy` с реальными настройками. HSTS включать лишь после проверки постоянного домена.

### MVP-06 · Нет ограничения попыток входа — подтверждено

[LoginView](../backend/apps/accounts/views.py) проверяет пароль, но в API/на прокси не настроены лимиты запросов или блокировка перебора; в [настройках DRF](../backend/config/settings.py) нет throttling. Известные демо-логины усугубляют риск на публичном стенде.

**Закрытие:** лимит входа по IP и учётной записи с тестами на 429/восстановление, не раскрывая существование пользователя через сообщения об ошибке.

### MVP-07 · Нет CI и защиты `main`/`develop` — подтверждено

В репозитории нет `.github/workflows`; GitHub не показывает обязательных проверок и protection для обеих постоянных веток. Подготовленный workflow не удалось отправить через текущий OAuth-доступ: GitHub требует scope `workflow`. Локальные 29 backend- и 35 frontend-тестов не заменяют повторяемую проверку каждого PR.

**Закрытие:** доступ с правом `workflow`, CI для тестов/миграций/typecheck/build на PR, затем обязательные проверки и review для `develop` и `main`. Не переносить `develop` в `main` до принятия MVP.

### MVP-08 · Резервируется только БД, не файлы работ — подтверждено

[`backup-db.sh`](../scripts/backup-db.sh) и [`restore-db.sh`](../scripts/restore-db.sh) сохраняют PostgreSQL. Загруженные работы лежат в отдельном Compose-томе [`media_data`](../docker-compose.yml); скриптов и процедуры резервного копирования/восстановления этого тома нет. Восстановление одной БД оставит ссылки на отсутствующие файлы.

**Закрытие:** согласованный backup БД и media с проверкой восстановления файла ученика и доступа к нему; испытать процедуру на копии стенда.

### MVP-09 · Python зависит от внешнего CDN и не имеет жёсткого лимита всей памяти — подтверждено

[Pyodide](../frontend/src/features/student/pythonWorker.ts) загружается с jsDelivr. При недоступности CDN алгоритмические шаги не работают. `tracemalloc` измеряет только часть Python-аллокаций; метрика приходит от клиента и не ограничивает всю память WebAssembly/браузера.

**Закрытие:** проверить загрузку на целевом стенде и в сети жюри, при необходимости раздавать зафиксированный runtime локально. Для доверенной оценки закрыть MVP-02 серверным лимитом ресурсов.

### MVP-10 · Учебный пакет организатора — локально закрыт, стендовая приёмка открыта

Кейс, раздел 09, предусматривает базовый пакет **реального** учебного содержания и брендбук. Материалы получены, карта привязана к SHA-256 DOCX, а [`seed_demo`](../backend/apps/accounts/management/commands/seed_demo.py) и [`import_curriculum`](../backend/apps/courses/management/commands/import_curriculum.py) создают и публикуют 3 курса, 9 модулей и 30 шагов с суммами 10/8/12. При этом реальные персональные данные добавлять нельзя, а локальная проверка не заменяет приёмку на HTTPS-стенде.

**Закрытие локального этапа:** материалы проверены, весь пакет перенесён и повторный импорт покрыт тестами. **Остаётся:** пройти публикацию/назначение/прохождение на стенде и зафиксировать результат в E2E-журнале.

### MVP-11 · Нет автоматизированной сквозной проверки — подтверждено

Есть API- и компонентные тесты, но нет теста полного браузерного пути «администратор → ученик → куратор → прогресс», Nginx-маршрутизации, TLS и восстановления. Исправленный ранее конфликт `/admin/` не проверен в запущенном production-образе.

**Закрытие:** добавить хотя бы один E2E smoke на Compose/HTTPS или воспроизводимый ручной протокол с датой, URL, версиями и результатом каждого шага; затем автоматизировать критические переходы.

### MVP-12 · `main` не содержит текущий продукт — подтверждено

По GitFlow рабочий код интегрирован в `develop`, а default-ветка `main` осталась на документационном релизе и на этом срезе отстаёт на 52 коммита. Если жюри откроет репозиторий по умолчанию, оно не увидит текущий MVP. Это не повод преждевременно выпускать непроверенный продукт, но обязательный пункт перед стоп-кодом.

**Закрытие:** после решения P0 и стендовой приёмки открыть release PR из `develop` в `main`, проверить его, обновить README с публичным URL и пометить релиз тегом.

## P2 — качество, удобство и рост

### MVP-13 · Статус приостановленного назначения не объяснён ученику — подтверждено

[Страница шага](../frontend/src/features/student/StudentStepPage.tsx) не получает статус enrollment и оставляет форму сдачи активной. Сервер отклоняет отправку для `paused`/`completed`, поэтому ученик узнаёт о запрете только после ошибки.

**Закрытие:** показывать статус курса и причину запрета до отправки, блокировать форму, покрыть тестом.

### MVP-14 · Страница куратора строит все данные до пагинации — подтверждено

[`CuratorStudentsView`](../backend/apps/mentoring/views.py) загружает все назначения, строит прогресс и сигналы по каждому, а **затем** разбивает список учеников на страницы. Количество SQL-запросов и время ответа растут вместе со всей базой, даже если открыта первая страница.

**Закрытие:** сначала пагинировать пользователей/назначения, затем считать прогресс только для текущей страницы; проверить число запросов и время на увеличенном синтетическом наборе.

### MVP-15 · Новый тип шага требует синхронных правок в нескольких слоях — риск расширяемости

Типы перечислены в [backend-реестре](../backend/apps/courses/step_types.py), [сериализаторах сдачи](../backend/apps/grading/serializers.py), [проверке](../backend/apps/grading/services.py), [формах администратора](../frontend/src/features/admin/StepEditorForm.tsx) и [формах ученика](../frontend/src/features/student/SubmissionPanel.tsx). Седьмой тип удалось добавить, но нет единого контрактного теста, который гарантирует поддержку типа во всех слоях. Это риск для требования кейса о расширяемости, не доказанный сбой текущих семи типов.

**Закрытие:** общий каталог возможностей/контрактные тесты для каждого зарегистрированного типа и документированная процедура добавления типа; проверить восьмой тестовый тип.

### MVP-16 · Проверка вложений поверхностная — подтверждено

[`_validate_file`](../backend/apps/grading/services.py) проверяет размер, расширение и несколько первых байтов, но не структуру ZIP/PDF, вредоносное содержимое и безопасное извлечение. Сейчас файлы скачиваются как вложения и не исполняются сервером, поэтому это прежде всего риск для куратора при открытии недоверенных работ.

**Закрытие:** предупреждение куратору, ограничения типов по реальному содержимому/антивирусная проверка при публичной эксплуатации, запрет автоматического извлечения архивов, тесты повреждённых файлов.

### MVP-17 · Часть документации отражает старые срезы — подтверждено

Исторические [frontend-handoff](frontend-audit-handoff.md) и [DEV-3 handoff](dev3-handoff.md) содержат старые количества тестов и формулировки о функциях, которые уже добавлены; в [user-flows](user-flows.md) всё ещё указано отсутствие контекста задания для куратора, исправленное PR #24. Документы помечены как исторические, но без явной ссылки на этот реестр читатель может принять их за текущий статус.

**Закрытие:** актуальный статус читать здесь и в [сверке с кейсом](case-alignment.md); в исторических файлах добавить заметные даты/ссылки, убрать устаревшие утверждения из документов, позиционируемых как текущие.

### MVP-18 · Невлитые дизайн-ветки не оценены — не проверено

`feature/brandbook` и `feature/theme-refinement` не входят в `develop`. Они содержат черновой брендбук и статический прототип, не рабочие экраны. Их не следует автоматически сливать ради количества функций, но соответствие интерфейса брендбуку организатора пока не подтверждено.

**Закрытие:** сравнить готовый UI с предоставленным брендбуком, принять полезные элементы отдельным PR или закрыть ветки как архивные после решения команды.

## Уже исправлено — не считать открытыми дефектами

- PR #23: тип `quiz.multiple_choice`, объяснение, почему черновой курс нельзя назначить, правило публикации «только теория» по решению владельца.
- PR #24: публичная маршрутизация React `/admin/*` через Nginx, контекст задания для куратора, защищённые cookie в HTTPS-профиле и отказ от известных примерных Django-ключей.

Эти изменения прошли локальные тесты, но production-маршрут и TLS всё ещё требуют проверки по MVP-03/MVP-11.
