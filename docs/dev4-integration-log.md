## Протокол следующей приёмки

После схемы DEV-1 DEV-4 запускает
транзакционный повторяемый импорт, публикует версии и назначает только
синтетические аккаунты. Журнал каждого прогона должен содержать дату и время,
коммит, URL стенда, SHA-256 исходного DOCX, количество созданных/обновлённых/
пропущенных записей и итог. Повторный запуск должен давать ноль дублей и не
изменять существующие назначения или попытки.

Для каждого перехода сквозного сценария записывать роль синтетического
пользователя, операцию/маршрут, HTTP-статус, наблюдаемый результат и
`X-Request-ID` либо `meta.request_id`. По этому идентификатору находить запись
API в request-id логах. Не помещать в журнал ответы, эталонные решения,
содержимое сдач, токены и персональные данные. Отдельно фиксировать проверку
старого назначения после новой публикации, отказ в зачёте по поддельному
клиентскому Python-результату, лимиты исполнителя и результат backup/restore.
