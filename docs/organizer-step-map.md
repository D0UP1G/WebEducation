# Карта шагов пакета организатора

Источник: [оригинальный пакет](organizer/basic-curriculum.docx). Это карта соответствия для импорта DEV-4 и проверки DEV-3; исходный DOCX остаётся неизменным. `type_key` определяет способ сдачи и проверки, а исходное название шага и педагогический контекст сохраняются в курсе. Режимы: `instant` — серверная проверка ответа, `manual` — решение куратора, `browser` — текущий браузерный протокол Python, который **не даёт защищённого зачёта**. Для официального Python-зачёта нужен отдельный изолированный серверный запуск.

Итого: Scratch — 10 шагов, Minecraft Education — 8, Python — 12; всего 3 курса, 9 модулей и 30 шагов. Все девять `type_key` доступны в реестре типов этой ветки. Каждый курс содержит теорию и контрольный вопрос. Это отображение покрывает механизмы сдачи, но не является импортом содержания: модели модулей, паспорта курса и сами draft ещё ожидают работу DEV-1/DEV-4.

**Интеграция с DEV-4:** параллельный PR #33 добавляет полную машиночитаемую `docs/organizer/curriculum-map.json`. Перед импортом в ней нужно заменить для шага 1.1.3 `type_key: answer.exact` на `scratch.numeric_answer` и обновить проверку карты. Исходный педагогический тип в PR #33 уже сохранён, но новый отдельный тип позволит отобразить его в редакторе и интерфейсе ученика. Остальные целевые типы из карты согласуются с таблицей выше.

При переносе правильные ответы и критерии должны храниться в данных сервера и не выходить через ученический API. Однако оригинал DOCX уже находится в публичном Git, поэтому опубликованные там ответы и помеченные «скрытыми» тесты доступны читателям репозитория. Не считать их секретными тестами. Для Minecraft и проектов правила обязательной комбинации доказательств ещё нужно выразить в схеме шага: текущий валидатор принимает любой один файл **или** ссылку и необязательное пояснение. Критерии куратора пока не имеют отдельного закрытого поля. Отдельный PR DEV-3 должен добавить эти ограничения и ролевую проверку до импорта.
