# DEV-3: подсказка после неверного ответа Scratch

Срез: feature-ветка `codex/dev3-scratch-feedback` от `develop` после PR #42, 24.09.2026. Источники: [кейс §§04–05](../keys-obrazovatelnaya-platforma.pdf), [учебный пакет](organizer/basic-curriculum.docx), [карта шага 1.1.3](organizer/curriculum-map.json), [архитектура](../ARCHITECTURE.md) и [текущие задачи](team-work-plan.md).

## Что изменено

- Для `scratch.numeric_answer` добавлено необязательное серверное поле `content.feedback_after_incorrect`: непустая строка до 5000 символов. У обычного `answer.exact` поведение прежнее.
- Preflight переносит список `private_assessment.feedback_after_incorrect` шага 1.1.3 в эту строку, сохраняя порядок и переносы строк; неправильный формат останавливает план до записи в БД.
- Ученический GET шага и назначения скрывает подсказку вместе с правильным ответом. После неверной сдачи подсказка попадает в `Submission.feedback` ответа POST и истории собственных попыток. При правильной сдаче возвращается «Верно». Старые Scratch-шаги без подсказки возвращают «Попробуйте ещё раз».
- Администратор может редактировать закрытое поле в draft. Публичный DOCX содержит ту же подсказку: ролевой API скрывает её до попытки, но не обеспечивает секретность текста за пределами приложения.

## Проверка

Локально: весь backend-набор — **71 тест, OK**; preflight — **3 курса / 9 модулей / 30 шагов**, `makemigrations --check --dry-run` — **No changes detected**. Проверены отсутствие подсказки в student GET/preflight, её появление только после неверной сдачи, история, правильная сдача и отказ чужому ученику. Миграции не нужны: используется существующий JSON `content` и `Submission.feedback`.

## Что остаётся

DEV-4 после идемпотентного импорта курсов проверяет шаг 1.1.3 на реально записанной ревизии: до ответа подсказки нет, после неверного она есть, после верного балл начислен один раз. DEV-1/DEV-3 по отдельному контракту продолжают защищённый официальный Python-зачёт; этот PR не меняет браузерную Python-проверку.
