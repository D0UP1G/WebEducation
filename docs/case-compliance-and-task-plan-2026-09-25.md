## 4. Концепция решения для Python (Таска 1)

Согласно требованиям и решению команды:
1. **Локальное исполнение в браузере (самопроверка)**:
   - Сохраняется для мгновенного отклика и удобной отладки учеником без ожидания очереди.
   - Выполняется через Web Worker (Pyodide).
   - Запускается по кнопке **«Проверить тестовый пример»**; свой ввод остаётся локальным и не получает официальную оценку.
   - **Не отправляет сдачу на сервер, не создает записей `Submission` и не начисляет баллы**.
   - Показывает ученику фактический `stdout`, ошибки выполнения и время запуска на открытых тестах/примерах.
2. **Официальная сдача решения**:
   - По кнопке **«Отправить на проверку»** фронтенд отправляет на сервер исключительно код: `{"code": code}`.
   - Браузерные результаты (`stdout`, `duration_ms`, `peak_memory_bytes`) сервером не принимаются и не запрашиваются.
   - Сервер самостоятельно выполняет код в изолированной среде:
     - Ограничение времени CPU и wall-clock timeout (`time_limit_ms`).
     - Ограничение оперативной памяти (`memory_limit_mb`).
     - Ограничение размера вывода (`output_limit_bytes`).
     - Изолированный временный каталог без доступа к секретам проекта, БД и внешней сети.
     - Сопоставление с эталонным выводом закрытых тестов.
   - Сервер выставляет официальный статус (`accepted`, `incorrect` или `error`), начисляет баллы и возвращает безопасную диагностику (число пройденных тестов и причину непрохождения).

## 5. Очередь задач (Критический путь)

Задачи выполняются строго последовательно по **GitFlow**: каждая задача реализуется в ветке `feature/<task>`, покрывается тестами и отправляется Pull Request в `develop`.

```text
[P0-1: Полный E2E трёх ролей на пакетах 3/9/30]
                      ↓
[P0-2: Публичный стенд Docker Compose + Cloudflare Tunnel]
                      ↓
[P0-3: Приёмка восстановления данных и финализация README]
                      ↓
[P0-4: Release PR в main]
```

### Таска 1. Изолированный серверный runner Python и разделение самопроверки

**Статус:** PR #50 влит в `develop`. Локальный Docker Compose с браузерной самопроверкой и исходами `wrong_answer`, `time_limit`, `accepted` пройден; новые варианты Python после зачёта также проходят серверную проверку, а прежний зачёт и баллы сохраняются. Публичный HTTPS-стенд и E2E на официальном пакете остаются открытыми. [Подробный аудит](python-runner-audit-2026-09-25.md).

- **Ветка**: `codex/python-server-runner`
PR #50 разделил локальную самопроверку через Pyodide и официальную сдачу: API принимает только код и отправляет его в изолированный runner. Runner применяет временные и ресурсные лимиты, сравнивает все тесты и возвращает безопасную диагностику; клиентский `stdout` на зачёт не влияет.

### Таска 2. Модель модулей, паспорт курса и импорт пакета 3/9/30
**Статус:** модель и импорт реализованы в PR #51, официальный seed и отображение модулей — в PR #52. Добавлены миграция `0002_curriculum_structure`, поля паспорта, `Module`/`ModuleRevision` и транзакционный импорт карты по стабильным `source_id`. Команда `import_curriculum --publish` создаёт/обновляет три курса; `seed_demo` оставляет только официальный пакет и чистые назначения, без синтетического курса и фиктивных сдач. Тесты проверяют суммы 10/8/12, группировку, повторный импорт и чистый seed.

### Таска 6. Поэтапное прохождение и Python-редактор
**Статус:** PR #54 влит в `develop`; ограничения доступа на API и CodeMirror-поддержка проверены. Импортированный курс и публичный стенд требуют E2E.

- Доступ к каждому шагу, отправкам, вопросам и Python-примеру проверяется на
  сервере: все шаги с меньшей позицией должны иметь статус `accepted`.
- Enrollment выдаёт только метаданные списка шагов; содержимое загружается по
  отдельному endpoint для открытого шага. В прогрессе появляется `unlocked`.
- В ученическом курсе будущие шаги видны как закрытые; pending review также
  блокирует продвижение.
- CodeMirror 6 предоставляет Python-подсветку, встроенные и локальные подсказки,
  сниппеты, автозакрытие скобок и кавычек, автоотступ и Tab для отступа.
- В ручном Vite-прогоне проверены продвижение после зачёта теории и вопроса,
  автозакрытие `[]`, Tab/автоотступ, `Ctrl+Space` с подсказкой `print` и локальный
  запуск открытого Python-примера. Видимую строку клавиатурной помощи удалили.
- Fallback генерации UUID добавлен для HTTP-страниц в LAN, где недоступен
  `crypto.randomUUID()`. Перед приёмкой необходимо пересобрать текущий Compose,
  запустить `seed_demo`, затем проверить серверную Python-сдачу и полный
  сценарий на импортированном курсе. Подсказки CodeMirror не являются
  полноценным Python LSP.
