# План демо на одном хосте

Актуальные статусы и порядок задач указаны в
[плане от 25.09.2026](case-compliance-and-task-plan-2026-09-25.md).
Этот файл фиксирует практическую схему стенда для одного агента.

```text
Интернет → Cloudflare Tunnel → proxy (единственная публичная точка)
                                  ├─ React
                                  └─ web (Django API) → db (PostgreSQL)
                                          └─ Unix-сокет → runner (без сети)
```

1. PR #50 с локальной самопроверкой и официальным runner уже в `develop`.
   Локальный Compose-прогон правильного, неверного и бесконечного Python-кода,
   а также сетевой изоляции runner пройден 25.09.
2. PR #51/#52 добавили модель модулей, паспорт курса, официальный demo seed и
   импорт пакета организатора: 3 курса, 9 модулей, 30 шагов. Ветка
   `feature/stepwise-python-editor` добавляет открытие шагов только после
   зачёта предыдущего и улучшает Python-редактор. На Docker-хосте проверить
   последовательный сценарий на официальном курсе.
3. Развернуть Compose на целевом компьютере/VPS. Настроить `.env` с уникальными
   секретами и Cloudflare Tunnel к `proxy`; наружу не открывать PostgreSQL,
   Django или runner. Проверить healthcheck, перезапуск и сохранность БД/media.
   PR #53 влит в `develop`: backend image включает подготовленную JSON-карту,
   а runtime-импорт не требует исходный DOCX. Первый запуск команды был собран
   до этого исправления и завершился `FileNotFoundError`; теперь нужно повторно
   собрать Compose и проверить `seed_demo`, API и runner. На уже заполненном
   volume `seed_demo` добавит официальные курсы и назначения, сохранив старый
   синтетический курс и историю попыток. Чистый тестовый стенд следует
   готовить на новом volume после сохранения нужных данных.
4. Пройти E2E: администратор публикует и назначает → ученик видит группы модулей,
   не может пропустить шаг, изучает теорию, отвечает, локально проверяет Python
   и сдаёт его официально → куратор
   возвращает ручную работу с комментарием → ученик пересдаёт → куратор
   принимает → прогресс и баллы обновляются.
5. Обновить README реальным URL и ограничениями; открыть release PR в `main`.

Для runner сейчас применяется последовательный синхронный запуск с общим
бюджетом 45 секунд. `queued/checking` остаются зарезервированными статусами;
при высокой нагрузке потребуется очередь. Исходный DOCX в публичном Git
содержит эталоны, поэтому для проверки, устойчивой к подгонке, понадобятся
дополнительные тесты вне публичного пакета.
