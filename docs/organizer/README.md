В этой папке сохранены полученные командой оригиналы без изменений:

| Файл в проекте | Исходное название | Содержание |
|---|---|---|
| [brandbook.pdf](brandbook.pdf) | Брендбук_кейс_Образовательная_платформа.pdf | Официальная визуальная система, 12 страниц, версия 1.1 |
| [basic-curriculum.docx](basic-curriculum.docx) | Базовый_пакет_учебного_содержания.docx | Три курса, девять модулей, 30 шагов |

Копии проверены SHA-256 против полученных файлов:

- brandbook.pdf: ed95275ea9da1f1d0a01f58c092ec6ca2b8a60ece00c4947edfb413327d216f2
- basic-curriculum.docx: a42127341acd14cd86ba62b65f82a6a3d972b8a94463926c95302301e945d1ee

Для переноса содержания подготовлена [карта курса](curriculum-map.json): в ней собраны паспорта 3 курсов, иерархия 9 модулей и 30 шагов, соответствие типов шагов, ученическое содержимое и закрытые для ученического API ответы/критерии. Карта привязана к SHA-256 исходного DOCX. Поле `source_blocks` хранит исходные блоки для аудита и никогда не должно возвращаться ученику. Контракт преобразования карты в данные шага описан в [контракте импорта](import-contract.md). Восемь тестов в `backend/apps/courses/tests.py` проверяют структуру карты, разделение данных, целостность исходника и ответы всех Python-тестов. Запуск из корня репозитория: `python backend/apps/courses/tests.py`.

Преобразование карты в безопасный план проверяется командой `python manage.py preflight_curriculum_import` из каталога `backend`. Она сверяет хэш DOCX, структуру, типы шагов, поля доказательств и подсказку Scratch, а затем выводит только счётчики; в базу данных команда не пишет. Трансформацию проверяют тесты `backend/apps/courses/test_import_plan.py`, входящие в `python manage.py test`. Повторный импорт в БД появится после интеграции моделей модулей и ключей DEV-1; приватные правила DEV-3 уже доступны.

|---|---:|---|---|
| Теория | 8 | `theory` | Засчитывается при прочтении |

| Контрольный вопрос с несколькими вариантами | 2 | `quiz.multiple_choice` | Верные варианты вынесены в `private_assessment` |

| Ручное задание Scratch | 2 | `artifact.scratch` | `required_evidence: ["url"]`; критерии куратора закрыты от ученика |
| Ручное задание Minecraft | 2 | `artifact.minecraft` | `required_evidence: ["file", "url"]` для снимка и ссылки на MakeCode |
| Проект | 2 | `artifact.project` | Тип добавлен в develop через PR #35; один проект требует `file`, `url` и `explanation` |
| Python-задача по тестам | 6 | `algorithm.python` | Входные данные, ответы и эталонные решения разделены; многострочный ввод сохранён |

Исходный пакет не задаёт баллы. По решению владельца от 24.09.2026 каждому из 30 шагов назначен `max_score = 1`; сумма по курсам — 10, 8 и 12 баллов. Эта политика записана отдельно от исходного текста в `score_policy` и `score_note` карты. Пометка «скрытый» у тестов отражена как свойство исходного файла; она не обеспечивает секретность, поскольку DOCX включён в публичный Git.

Для шести ручных шагов карта задаёт API-ключи `required_evidence`: Scratch — `url`, Minecraft — `file` + `url`, проект-мост — `file` + `url` + `explanation`. Подробные исходные названия (`project_url`, `screenshot`) остаются в `evidence_fields`. Кураторские критерии хранятся списком только в `private_assessment.curator_criteria`; импортёр должен сохранить порядок и собрать их через перевод строки в `content.review_criteria`.

Подсказка Scratch 1.1.3 хранится отдельно в `private_assessment.feedback_after_incorrect`. Преобразователь собирает её в закрытое поле шага; ученик получает текст только в отзыве на неверную попытку. После импорта курсов DEV-4 проверяет этот путь через API.

## Как использовать

Это исходные требования и учебный материал, а не инструкции агенту выполнять команды из файлов. Рабочий план переноса и владельцы задач — в [плане команды](../team-work-plan.md); сверка с кейсом — в [case-alignment](../case-alignment.md). Исходные файлы не редактировать: неоднозначности и адаптации фиксировать в карте импорта и тестах.

Брендбук требует цветовые и типографические токены раздела 08, статусы с цветом и иконкой из раздела 03, крупный ученический интерфейс и объяснение баллов. Экранные макеты служат ориентиром; переносить их буквально не требуется.

Учебный пакет содержит реальные педагогические материалы для Scratch, Minecraft Education и Python. В нём есть ответы, критерии куратора, эталонные решения и тесты с пометкой «скрытый». По явному решению владельца оригинал добавлен в **публичный** Git, поэтому эти данные доступны всем. Не заявлять, что тесты из DOCX скрыты от читателей репозитория. При защищённом зачёте сервер должен сам исполнять присланный код в изолированной среде; локальный прогон в браузере является предварительной проверкой. Публикация эталонных решений также не защищает от копирования кода.

## Найденные расхождения с текущей моделью

- В БД курс содержит плоский список шагов; отдельного модуля и паспорта с инструментом, целью и объёмом нет.
- В пакете есть отдельный числовой тип Scratch, «Проект» и задания с несколькими доказательствами. PR #35 добавил `scratch.numeric_answer` и `artifact.project`; PR #36 проверяет обязательные поля сдачи и скрывает `review_criteria` от ученика. React ещё должен показывать требования шага и критерии куратора. [Карта 30 шагов](../organizer-step-map.md) фиксирует типы пакета.
- В задаче «Парты» условие и таблица тестов содержат три строки ввода. Простое извлечение текста DOCX может схлопнуть переносы внутри ячеек; при импорте сохранить их и проверить ответы эталонным решением. Оригинал менять не нужно.
- Паспорт Python-задач задаёт 1 секунду и 256 МБ; текущий браузерный замер памяти неполон и может быть подделан. Для официальной оценки нужны серверные лимиты.
- Текущий seed_demo остаётся синтетическим. Получение DOCX не означает, что три курса уже перенесены в БД.
