# Сверка репозитория с кейсом

Источник: [«Кейс: образовательная платформа»](../keys-obrazovatelnaya-platforma.pdf), 8 страниц. Состояние ниже сверено с `develop` после объединения PR #8 (ядро), #9 (интерфейс) и #10 (сдачи и проверка). «Реализовано» означает наличие работающего кода и тестов; полная приёмка на развёрнутом стенде указана отдельно.

| Требование кейса | Что есть в репозитории | Что нужно для проверки на стенде |
|---|---|---|
| Ученик входит, видит курсы, следующий шаг, историю | Auth, страницы ученика, прогресс, сдачи и история попыток подключены к API | Пройти все шесть типов в полном браузерном сценарии на стенде |
| Куратор видит своих учеников, очередь, возвращает и принимает работы, отвечает на вопросы | API и страницы куратора работают; права привязаны к назначению; сигналы застоя реализованы | Проверить полный сценарий; исправить отсчёт 72 часов после позднего ручного зачёта |
| Администратор собирает, публикует и меняет курс, назначает участников | Draft CRUD, preview, публикация версий, назначения и страницы администратора реализованы | Проверить через браузер публикацию новой версии и сохранность старого назначения |
| Шесть типов шагов и расширяемость | Реестр, валидация, рендереры, формы и синтетический seed для `theory`, `quiz.single_choice`, `answer.exact`, `algorithm.python`, `artifact.scratch`, `artifact.minecraft` | Пройти все типы в одном демонстрационном курсе |
| Автоматическая и ручная проверка | Quiz/exact проверяются на сервере; Python исполняется в Web Worker, а сервер сверяет вывод; Scratch/Minecraft попадают в очередь ручной проверки | Устранить случай истечения Python challenge до конца допустимого прогона; повторить ошибки, возврат и пересдачу на стенде |
| Прогресс и объяснимый рейтинг | `learning.services.build_progress` считает принятые шаги и баллы для авто- и ручной проверки; есть `next_action` и сигналы куратора | Проверить обновление после полного сценария и исправить дату последнего ручного зачёта |
| Учебные материалы и демонстрационные данные | `seed_demo` создаёт синтетический курс из шести шагов и три демо-аккаунта; пакет организатора в репозитории отсутствует | Использовать синтетический курс; если появятся внешние материалы, проверить права на публикацию |
| Исходный код, README, лицензия и браузерный стенд | Код трёх ролей, миграции, Compose, README и лицензия есть | Проверить Compose и HTTPS на целевом хосте, восстановление БД и файлов, опубликовать проверенный URL и повторить сквозной сценарий |

Локальная проверка: 18 backend-тестов, 25 frontend-тестов, проверка Django и
сборка Vite проходили при handoff DEV-3. В браузере проверена часть пути:
Python на двух тестах → Scratch-ссылка → возврат → пересдача → принятие →
прогресс `2/6`. Это не заменяет полный тест на публичном стенде.

## Решения для первого рабочего среза

1. **Шесть обязательных видов шагов.** `theory`, `quiz.single_choice`, `answer.exact`, `algorithm.python`, `artifact.scratch`, `artifact.minecraft` входят в P0. Scratch и Minecraft Education требуют задания с внешним результатом и ручной проверкой; встроенные редакторы этих сред не нужны.
2. **Единая оценка.** Принятый шаг даёт все `max_score` баллов ровно один раз; неверная автоответная попытка и возвращённая ручная работа дают ноль. `completion_percent = floor(100 × число принятых шагов / число шагов)`; `rating_percent = floor(100 × сумма баллов принятых шагов / сумма max_score)`. Для пустого курса публикация запрещена. В ответе прогресса показываются обе величины, вклад каждого шага и причина незавершённости.
3. **Статусы различаются по причине.** `incorrect` — автоматическая проверка выполнена, ответ не прошёл; `returned` — решение куратора с обязательным комментарием; `error` — технический сбой проверки. Повторная сдача создаёт новую попытку. Отладка системного сбоя не должна выглядеть для школьника как ошибка в ответе.
4. **Следующее действие.** Шаги доступны в опубликованном порядке и могут быть открыты повторно. Система рекомендует первый незачтённый шаг без ожидающей проверки. Если все оставшиеся работы ожидают куратора, показывает ожидание; после возврата рекомендует исправить работу. Принятый шаг повторно не оценивается.
5. **Ранний сигнал куратору.** Первый простой набор правил: нет зачтённого шага 72 часа после назначения или последнего зачёта; две неверные попытки за 24 часа на одном шаге; возвращённая работа не пересдана 24 часа. Сигнал показывается в списке закреплённых учеников с основанием и временем; пороги — настраиваемая гипотеза для демо, не требование организатора.
6. **Версии.** Публикация создаёт неизменяемую версию; назначения и попытки остаются на своей версии. Новые назначения используют последнюю опубликованную версию. Обновление курса не меняет историю ученика.

## Учебные материалы

Пакет организатора и его демоданные в репозиторий не поступили; команда
использует синтетический курс. Для защиты нужен доступный стенд, а не
ожидание внешних материалов. Если материалы появятся позднее, право на их
публикацию в открытом репозитории следует проверить до добавления.

## Приёмка ядра

На свежем стенде администратор публикует курс с шестью видами шагов и назначает синтетических ученика и куратора. Ученик проходит теорию и вопрос, решает задачу с точным ответом, отправляет неверное и затем верное решение Python-задачи, сдаёт Scratch- и Minecraft-результаты. Куратор возвращает одну работу с комментарием и принимает пересдачу, отвечает на вопрос по шагу. Ученик видит причины статусов, историю, изменение обоих процентов и баллы по шагам. Куратор видит сигнал застоя. После новой публикации старое назначение и его попытки сохраняют прежнюю версию. Этот сценарий должен пройти на развёрнутом URL, а инструкция в README должна позволять повторить локальный запуск.
