Срез: ветка `feature/dev3-evidence-criteria` от `develop` после PR #31. Это дополнение к [основному DEV-3 handoff](dev3-handoff.md). Сверено с [кейсом](../keys-obrazovatelnaya-platforma.pdf), [пакетом организатора](organizer/basic-curriculum.docx) и параллельной картой импорта DEV-4 в PR #33. Код этого PR работает с существующими `artifact.scratch` и `artifact.minecraft`; общие правила ручной проверки подготовлены и для `artifact.project` из PR #35.

## Контракт шага

В `content` ручного шага доступны необязательные поля:

```json
{
  "instructions": "Пришлите снимок, ссылку и короткое объяснение",
  "required_evidence": ["file", "url", "explanation"],
  "review_criteria": "Проверьте форму моста и действия агента"
}
```

`required_evidence` — непустой список уникальных значений `file`, `url`, `explanation`; нужен хотя бы `file` или `url`. Все перечисленные поля обязательны в **одной** попытке. Если поле отсутствует, действует прежнее правило: достаточно одного файла или одной ссылки; старые курсы и попытки не меняются. Пустое или состоящее из пробелов объяснение не считается доказательством. Файл по-прежнему проходит прежние проверки размера и сигнатуры; ссылка — проверку `http(s)`.

`review_criteria` — непустой текст до 10 000 символов. Он остаётся в draft и опубликованной ревизии, но исключён из ученического API, включая список шагов, детали и preview. Закреплённый куратор получает его в `step.content` очереди и карточки проверки. В вопросах используется обычное публичное представление шага; ключи автоответов куратору по-прежнему не выдаются. Администратор видит исходный draft.

## Правила для импорта пакета

| Шаг | `required_evidence` | `review_criteria` |
|---|---|---|
| 1.2.3, 1.2.4, 1.3.3 | `["url"]` | Критерии из паспорта шага |
| 2.1.3, 2.2.3 | `["file", "url"]` | Критерии из паспорта шага |
| 2.3.1 | `["file", "url", "explanation"]` | Критерии из паспорта шага |

Для 2.3.1 инструкция ученику указывает 2–3 предложения. Сервер проверяет наличие непустого пояснения; качество и объём текста оценивает куратор. DEV-4 переносит значения в draft после согласования схемы модулей и политики баллов с DEV-1. Оригинал DOCX менять не нужно. Критерии из DOCX доступны читателям публичного Git; ролевое ограничение предотвращает выдачу через ученический API, но не делает опубликованный исходник секретным.

`file` подтверждает наличие загрузки, но пока использует общий список форматов `.png`, `.jpg`, `.jpeg`, `.pdf`, `.sb3`, `.mcworld`. Для Minecraft сервер не доказывает, что файл именно снимок экрана; это проверяет куратор. При необходимости строгого формата DEV-1/DEV-3 согласуют отдельное ограничение типа файла в схеме шага перед импортом.
