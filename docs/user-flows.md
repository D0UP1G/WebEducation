# WebEducation — пользовательские потоки и страницы

PR #54 уже в `develop`. Описанные ниже улучшения реализованы в
`feature/user-flow-improvements` и ожидают PR review; не считать их уже влитыми
в `develop`. Проверки и соответствие кейсу и брендбуку сведены в
[аудит пользовательских сценариев](user-flow-remediation.md).

## Цель интерфейса

Администратор собирает и публикует курс, назначает его ученику и куратору;
ученик проходит шаги и отправляет работу; сервер автоматически проверяет её
или передаёт куратору; обе стороны видят понятные статус, обратную связь и
прогресс. В демо используются только синтетические аккаунты.

## Общая навигация и бренд

- `/login` показывает краткое назначение образовательной платформы отдельно от
  карточки формы входа; текст нейтральный, так как до входа роль ещё неизвестна.
- После входа роли открывают `/student`, `/curator/reviews` и `/admin/courses`;
  `/curator` перенаправляет в очередь.
- Навигация по разделам роли видна в шапке; выход — доступная иконка возле имени.
- У рабочих экранов общий footer. API отдельно проверяет роль и владение каждым
  ресурсом.
- Визуальные правила берутся из официального [брендбука](organizer/brandbook.pdf):
  существующие CSS-токены и шрифты Onest/JetBrains Mono, крупный текст и кнопки
  ученика, статус одновременно иконкой, цветом и подписью, без emoji. Ученику
  пишем на «ты», сотрудникам — на «вы».

## Ученик

Основной путь: `главная → каталог → курс → шаг → ответ или работа → результат →
следующий шаг`.

| Страница | Что видит ученик | API |
|---|---|---|
| `/student` | Ближайшее действие и кнопку продолжения; статистика ниже основного действия | `GET /student/courses`, `/student/enrollments/{id}/progress` |
| `/student/courses` | Только каталог назначенных курсов. Карточки целиком кликабельны; строки показывают завершённые шаги, оставшиеся шаги и процент. Есть баннер курса. | `GET /student/courses` |
| `/student/courses/{enrollment_id}` | Паспорт курса, модули, состояние шагов, баллы и следующий доступный шаг | `GET /student/enrollments/{id}`, `/progress` |
| `/student/courses/{enrollment_id}/steps/{step_id}` | Материал, задание нужного типа, форма сдачи, результат/история и переписка с куратором по этому шагу | `GET /student/enrollments/{id}/steps/{step_id}`, `/questions`, `/submissions` |
| `/student/profile` | Число пройденных и оставшихся шагов, баллы и прогресс по каждому курсу; без неподтверждённых рейтингов или серий | `/student/courses`, `/student/enrollments/{id}/progress` |

Курс следует материалам организатора: 3 курса, 9 модулей и 30 шагов. API
сохраняет плоский список шагов для совместимости, а интерфейс показывает их
группами модулей. Содержание будущего шага загружается только после открытия.
Шаг доступен, только если **каждый** предыдущий шаг имеет статус `accepted`.
Неверный ответ, сбой, возврат и ожидание куратора оставляют следующие шаги
закрытыми; API отвечает `404` на чтение, отправку, пример Python или вопрос по
закрытому шагу. Принятые шаги доступны для повторного просмотра.

В примере карты на странице 6 брендбука шаг на проверке у куратора не блокирует
следующий шаг. Для этого проекта владелец явно выбрал строгую последовательность
из исходного требования user-flow; пример макета отмечен как не применяемый к
этому правилу. Палитра, шрифты, статусы, плотность и остальные принципы
брендбука сохраняются.

### Python и теория

- Python-редактор CodeMirror 6 поддерживает подсветку, локальные подсказки,
  закрытие скобок и кавычек, Tab и автоотступ.
- Черновик кода сохраняется в браузере отдельно по курсу/шагу и восстанавливается
  после перезагрузки.
- «Проверить тестовый пример» запускает локальную самопроверку, не создаёт
  попытку и не начисляет баллы. Можно подменить входные данные и посмотреть
  фактический вывод. Оценка «верно/неверно» показывается только для исходного
  открытого примера. Свои входные данные остаются в браузере.
- «Отправить на проверку» отправляет код на сервер. Изолированный runner сам
  вычисляет официальный статус по всем тестам и ограничениям задания. Код и
  текст ошибки ученика сохраняются для возможности новой отправки; предыдущий
  зачёт Python и баллы остаются при проверке нового варианта.
- Теория отображается как Markdown: заголовки, списки, таблицы, ссылки,
  fenced code и изображения только по HTTPS-ссылке. Редактор курса даёт toolbar
  и предпросмотр; сырой HTML пропускается, изображения загружаются лениво и не
  отправляют Referer.

### Состояния и вложения

| API-статус | Подпись | Следующее действие |
|---|---|---|
| `queued` | Отправлено | Дождаться начала проверки |
| `checking` | Проверяется | Дождаться результата |
| `pending_review` | На проверке у куратора | Ждать решения; следующие шаги закрыты |
| `accepted` | Зачтено | Показать баллы и открыть следующий шаг |
| `incorrect` | Ответ не прошёл проверку | Показать безопасное объяснение и повторить |
| `returned` | Нужно исправить | Прочитать комментарий и пересдать |
| `error` | Ошибка проверки | Показать объяснение и предложить повтор |

Ручная сдача допускает файл, ссылку или оба поля, а также пояснение по
условиям шага. Поддерживаемые файлы: PNG, JPG, JPEG, WEBP, PDF, SB3 и MCWORLD;
сервер возвращает допустимый размер и перечень форматов при ошибке. PNG/JPG/
JPEG/WEBP показываются в защищённом предпросмотре ученику и закреплённому
куратору; другие форматы доступны через защищённую загрузку.

Переписка живёт внутри шага. Первый вопрос и все последующие сообщения видят
ученик и закреплённый куратор; отправка ответа не закрывает тред. Общего чата
нет.

## Куратор

| Страница | Что видит куратор | API |
|---|---|---|
| `/curator/students` | Только своих учеников, их курсы, прогресс и объяснимые сигналы застоя | `GET /curator/students`, `/progress` |
| `/curator/reviews` | Очередь работ `pending_review` | `GET /curator/reviews?status=pending_review` |
| `/curator/submissions/{id}` | Задание, попытки, файл/ссылку, защищённый предпросмотр фото и критерии из своего курса | `GET /curator/submissions/{id}` |
| `/curator/questions` | Все переписки учеников, шаг и его учебный контекст; форма для следующего сообщения | `GET /curator/questions?status=all` |

При любом решении по работе куратор обязан написать комментарий. Он показывается
ученику и при принятии, и при возврате; кнопка возврата подписана «Вернуть с
комментарием». Куратор не видит чужих учеников, попыток и переписок.

## Администратор

| Страница | Что видит администратор | API |
|---|---|---|
| `/admin/courses` | Черновики, опубликованные и архивные курсы; действие удаления/восстановления | `GET/POST /admin/courses`, `DELETE /admin/courses/{id}` |
| `/admin/courses/{id}/edit` | Паспорт и баннер, редактор курса и Markdown-теории, модули/шаги, порядок, предпросмотр и публикация | `GET/PATCH /admin/courses/{id}`, `/preview`, `POST/PATCH/DELETE .../steps`, `/publish` |
| `/admin/assignments` | Каждый ученик со списком его курсов и кураторов; отдельный поиск ученика, курса и куратора; добавление, снятие и изменение назначения | `GET /admin/users`, `GET/POST/PATCH /admin/enrollments` |
| `/admin/users` | Создание ученика/куратора, получение ссылки на первый пароль или сброс, отключение и удаление | `GET/POST /admin/users`, `POST /admin/users/{id}/password-link`, `PATCH/DELETE /admin/users/{id}` |

Опубликованная ревизия неизменяема. Черновой неопубликованный курс удаляется;
опубликованный архивируется, чтобы сохранить ревизии и работы. Архив нельзя
назначить; его можно восстановить. Снятие назначения записывает `removed`,
скрывает курс ученику и сохраняет все попытки и обсуждения. Повторное
назначение той же версии активирует прежнюю запись.

Пользователь создаётся без пароля. Сервер выдаёт одноразовый `setup_url`; по
сбросу старый пароль/токен аннулируется. Администратор передаёт ссылку сам —
сервис не отправляет письма. Удаление обезличивает аккаунт, отключает вход и
сохраняет учебную историю под подписью «Удалённый пользователь».

## Проверка и остающаяся приёмка

Данные карты 3/9/30 сверяются с DOCX, приватные правильные ответы и тесты не
выдаются ученику. CSS использует токены брендбука; акцентный жёлтый применяется
ограниченно, статусы показывают цвет + иконку + текст, язык экрана соответствует
роли. После локальных тестов остаются полный E2E на трёх импортированных курсах,
проверка на телефоне/планшете и внешний HTTPS-прогон через Cloudflare Tunnel;
они отмечаются отдельно от проверки unit/API.
