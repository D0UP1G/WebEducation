# Аудит адаптации дизайна WebEducation — 24 сентября 2026

## Источники и границы

Визуальные правила взяты из `docs/organizer/brandbook.pdf` (разделы 02–09),
`design/brand-tokens.css`, `design/webeducation-prototype.html` и
`design/AGENT-HANDOFF.md`. Прототип содержит шесть экранов с демонстрационными
данными и не задаёт API. Рабочие состояния берутся из React-компонентов и
ответов `/api/v1/`; рейтинговое место, серия дней и темп в очереди без полей
контракта не изображаются.

| Экран прототипа | Рабочий маршрут | Что адаптировано |
| --- | --- | --- |
| Ученик · курсы | `/student/courses` | Следующий шаг, тёмный hero, реальные баллы по источникам, сегментированная шкала и карта шагов. |
| Ученик · шаг | `/student/courses/:enrollmentId/steps/:stepId` | Условие и действие слева, компактный маршрут справа, результат из API. |
| Куратор · очередь | `/curator/reviews` | Плотная таблица, время ожидания от `created_at`, статус, переход к работе; пустое состояние. |
| Куратор · проверка | `/curator/submissions/:submissionId` | Доказательства и история рядом с решением; комментарий обязателен при возврате. |
| Администратор · редактор | `/admin/courses/:courseId/edit` | Контур шагов с иконками, редактор, предпросмотр и публикация версии. |
| Администратор · назначения | `/admin/assignments` | Форма и список назначений в двух колонках с реальными опубликованными версиями. |

Соседние маршруты без отдельного макета — обзор, ученики и вопросы куратора,
список курсов и пользователи администратора — приведены к тем же верхней панели,
табличным строкам, карточкам, статусам и плотности. В рабочем приложении есть
меню «Разделы» для навигации и выхода; в демонстрационном прототипе этого
элемента нет.

## Сверка с брендбуком

- Рабочий CSS импортирует `design/brand-tokens.css` как единый источник палитры,
  шрифтов, отступов и радиусов. Docker build stage копирует этот файл перед
  сборкой Vite.
- Onest — основной шрифт; JetBrains Mono — код и числовые значения. Ученические
  экраны сохраняют более крупную шкалу, рабочие экраны — плотную.
- Тёмный градиент оставлен только в hero следующего шага. Новых цветов,
  градиентов кнопок и эмодзи нет.
- Статус содержит иконку и текст. Для зелёного, янтарного и красного статусов
  фирменный цвет сохранён у иконки, а подпись сделана цветом «Чернила»:
  контраст исходной цветной подписи на фирменном светлом фоне составлял
  приблизительно 3,55:1, 4,46:1 и 4,11:1 соответственно — ниже 4,5:1.
- Для «Не начато» используется вариант токенов раздела 08: `#5E677D` с
  фоном `#F0F2F6`. Разницу с разделом 03 (`#8A93A8`) не скрывать.
- Следующий шаг берётся из `progress.next_step_id` и `progress.next_action`.
  На карте ожидающая ручная проверка не блокирует другой открытый шаг.

## Проверка и ограничения

- `npm run typecheck`, `npm test` и `npm run build` проверяют типы,
  API-сценарии, компоненты и production Vite build. Итоговый результат указан в PR.
- В рабочем браузере проверены страница учеников и пустая очередь куратора,
  раскрытие прогресса и меню. Проверены широкая ширина 1280 px, обычное окно
  около 613 px и минимальная ширина 320 px; глобального горизонтального
  переполнения нет, таблица прокручивается внутри карточки.
- При повторной загрузке локальный Vite отдавал пустой HTTP 502 на `/api/`,
  потому что Django на порту 8000 был остановлен. После запуска backend
  страница учеников снова загружается с реальными данными. Это окружение,
  не ошибка формата ответа React-компонента.
- Ученические и административные экраны покрыты компонентными тестами, но
  отдельная браузерная визуальная приёмка под этими ролями ещё нужна.
- Docker CLI доступен, но Docker daemon в текущем окружении не запущен:
  `docker build --target frontend-build` не смог подключиться к
  `/var/run/docker.sock`. Production image не собран здесь; корректность COPY
  проверена по Dockerfile и локальной production-сборке.
- Шрифты пока загружаются из Google Fonts; на офлайн-стенде требуется проверить
  загрузку или разместить файлы локально.
- Модули, паспорт курса, обязательные доказательства и закрытые критерии
  куратора требуют нового контракта backend. Не добавлять для них фиктивные
  поля только ради совпадения с макетом.
