# Frontend WebEducation

React + TypeScript клиент трёх ролей. Рабочие экраны используют цвета,
типографику, плотность по ролям и статусы официального брендбука v1.1.
Все API-запросы идут на `/api/v1/`
с сессионными cookies и CSRF-токеном.

## Локальный запуск

Сначала запустите Django на `http://localhost:8000` и выполните `seed_demo`
по корневому README, включая переменную `DJANGO_CSRF_TRUSTED_ORIGINS` для
локального входа. Затем:

```bash
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173/`. Демо-логины: `admin_demo`,
`student_demo`, `curator_demo`; пароль `demo`.

## Проверка

```bash
npm run typecheck
npm test
npm run build
```

Production build собирается при `docker compose up --build`; nginx отдаёт
файлы React по `/`, включая кабинет администратора `/admin/`, а API проксируется по `/api/`.
Django admin доступен только при прямом локальном запуске backend на порту 8000.

## Текущее подключение

- Работают с текущим backend: auth, каталог/шаги/прогресс ученика, редактор
  курсов, предпросмотр, публикация и назначения администратора.
- UI сдач, вопросов и куратора подключён к API. Ручная сдача отправляет файл,
  ссылку и пояснение в одной попытке; куратор видит все три элемента.
- На Python-шаге «Проверить тестовый пример» запускает локально поставляемый
  Pyodide в Web Worker. Можно задать собственный ввод и посмотреть вывод без
  оценки; правильность показывается только для открытого примера. Запуск не
  создаёт попытку и не начисляет баллы. «Отправить на проверку»
  передаёт серверу только код; статус и баллы возвращает отдельный изолированный
  runner. `npm run dev` и `npm run build` автоматически копируют Pyodide из
  установленного npm-пакета в статические файлы; CDN не требуется.
- Модули, паспорт курса и импорт 3/9/30 уже подключены. Текущая ветка
  `feature/user-flow-improvements` добавляет каталог с прогрессом и баннерами,
  профиль ученика, поиск и группировку назначений, непрерывные переписки,
  Markdown-теорию и защищённые превью изображений; полный список и приёмка — в
  [аудите user-flow](../docs/user-flow-remediation.md).

Шесть экранов статического [прототипа](../design/webeducation-prototype.html)
перенесены в рабочие React-маршруты: курсы и шаг ученика, очередь и проверка
куратора, редактор и назначения администратора. Разметка привязана к текущим
API и сохраняет рабочие действия; макетные имена и цифры не копируются.
Рабочие стили напрямую импортируют [токены дизайна](../design/brand-tokens.css),
а Docker-сборка копирует этот файл в build stage. В шапке постоянно видны
разделы текущей роли, а выход находится рядом с аккаунтом; на узком экране
навигация прокручивается по горизонтали. Соседние рабочие экраны (ученики и
вопросы куратора, списки курсов и пользователей) используют
те же таблицы, карточки и плотность, хотя отдельных макетов для них нет.
Демонстрационные «рейтинг в группе», серия и темп в очереди не перенесены —
этих полей нет в соответствующих ответах API. Прогресс и баллы выводятся по
настоящим шагам и попыткам.
